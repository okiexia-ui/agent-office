# 对话与 Visual 工作台

首页采用左右协作布局：左侧始终显示 3D 办公室与当前分工，下方展示成果和执行记录；右侧默认打开办公室群聊，顶部直接列出伙伴和状态。点击场景成员、任务或发言头像可切换到私聊；点击「一起群聊」返回团队。成果区可展开并恢复分屏。手机上方保留办公室、下方群聊，点击成果卡片打开成果面板。旧版完整办公室保留在 `/office.html`，任务管理与连接配置继续可用。

群聊中的 @ 点名会高亮，成果卡片对应实际交付者；引用同事消息不会把同事的成果误挂到自己名下。演示中的办公室与群聊使用一致的伙伴状态，不受旧版演示进度影响；全部示例仍明确标为演示。

## 能力与实际边界

- 延续现有私聊和群聊历史、引用回复、点名提醒，以及稳定请求 ID 的失败重试。
- 本机模式从本机办公室目录读取记录，远程部署从 R2 读取。工作台每 4 秒用一个 `/api/sync` 请求刷新消息、成果与执行步骤，无变化时返回 304。
- 每位 Agent 仍对应一份私聊历史，公共频道对应一份群聊历史；尚未引入任意数量的新会话或多群组。
- 成果支持文档（基础 Markdown）、横向柱状图、表格和自包含交互 HTML。
- 执行步骤由 Agent 实际汇报。工具名称是它提供的记录，不是服务器验证过的执行凭证。
- 本机启动器运行 Pi 和工作室中启用的 API 成员。远程 Hermes 依赖原有进程持续检查收件箱。模型服务使用该连接自己的凭证和额度。
- `?demo=1` 有独立的本地示例记录，全部标为演示。真实模式不自动生成占位回复。

## 在本机发起共享交付

在输入框旁的「交付形式」选择所需格式并说明要做的工作。群聊中请点名负责人。私聊也能发起交付，生成的成果会对全办公室可见。要单独讨论草稿，保留「普通消息」并直接提问。

| 交付形式 | 适合的请求 | 下载内容 |
| --- | --- | --- |
| 共享文档 | 根据给定的改动整理发布说明 | Markdown 正文（.md） |
| 共享表格 | 将材料按版本、改动、负责人归列 | 带列名的 CSV |
| 共享图表 | 根据给出的各组数值画对比图 | 图表数据 CSV，含标签、数值与单位 |
| 交互 HTML | 制作带筛选按钮的自包含清单 | 可离线打开、在隔离框中运行的 HTML |

也可在消息或任务标题的开头使用 `/visual document`、`/visual table`、`/visual chart` 或 `/visual html`。例如，将任务命名为 `/visual chart 按周绘制处理量：第一周 18，第二周 26`，再分配给启用的本地成员。

交付后从回复卡片或左侧「成果」打开成品，再按文件格式下载。输入里的数字和材料不足时，成员可以说明缺少的内容。打开「执行记录」可核对发布完成或生成失败的记录，按成员查看时可以连同其交付成果一起核对。来自消息和任务的成果分别关联原消息或任务。

## 成员与模型连接

在本机「创建 Agent」里可创建成员、修改其工作指令或复用模型连接。模型 ID 可以从服务获取，也可以手动填写。勾选清除密钥并保存可清掉已有密钥。删除连接前，所有引用该连接的成员都需先改选模型。停用一位成员会暂停其执行中的任务，保留成员和历史，重启后继续停用。重新启用后可在任务页继续之前暂停的工作。本地版仅保留远程 Hermes 接入配置。[本机操作步骤](LOCAL-PI.md)

## 供 Agent 调用的 5 个成果与记录工具

原有 12 个工具继续有效，总数为 17。

| 工具 | 用途 |
| --- | --- |
| `office_publish_visual` | 发布成果，可关联 `message_id` 和 `task_id` |
| `office_list_visuals` | 按伙伴、消息或任务读取成果元信息 |
| `office_get_visual` | 根据 `visual_id` 读取完整内容 |
| `office_report_step` | 汇报 `started`、`completed`、`failed` 或 `info` 执行记录 |
| `office_get_steps` | 按序号增量读取执行记录，支持相同过滤条件 |

示例：Agent 读取一条用户消息后，先汇报实际开始的步骤，再发布成果并通过原有回复工具答复。

```json
{
  "agent_id": "hermes",
  "request_id": "chart_actual_result_1",
  "title": "任务完成情况",
  "kind": "chart",
  "summary": "由已核对的数据汇总。",
  "message_id": "实际消息ID",
  "content": "{\"labels\":[\"已完成\",\"待处理\"],\"values\":[3,2],\"unit\":\"项\"}"
}
```

以上参数传给 `office_publish_visual`；数值只是接口示例，实际调用应使用真实结果。任务关联必须属于发布的 Agent；私聊消息同样校验归属；公共频道消息可供成员共同引用。Agent ID 沿用现有的同一办公室信任边界，不构成独立身份认证。

图表 `content`：`{"labels":["A","B"],"values":[-2,5],"unit":"项"}`，1–40 个标签与有限数值。表格 `content`：`{"columns":["名称","数量"],"rows":[["A",2],["B",3]]}`，最多 12 列、100 行。文档和 HTML 直接提供字符串内容，单份最多 32,000 字符。

同一 `request_id` 只可重试相同请求。修改结果时发布新成果，不覆盖旧版本。当前保留最新 40 份成果和 200 条执行记录；步骤序号单调递增，`history_truncated` 表示较早记录已经裁剪。重试去重仅适用于仍保留的记录，不是永久档案。

浏览器只读接口：`GET /api/visuals`、`GET /api/visuals/:id`、`GET /api/steps`。列表可用 `agentId`、`taskId`、`messageId` 过滤；步骤支持 `after` 序号。写入通过 MCP，沿用现有访问认证与 R2 条件更新。旧 `/api/state` 不返回成果正文或执行记录，浏览器保存成员与任务也不能覆盖它们。

## HTML 预览

HTML 放在带 `sandbox="allow-scripts"` 的 iframe 中，不允许 `allow-same-origin`、顶层跳转、弹窗或表单。前置 CSP 限制外部脚本、网络请求和嵌套框架；自包含的内联脚本、内联样式、data 图片可以运行。HTML 不直接插入工作台文档。作品中的链接或外部库可能无法工作；应优先发布自包含内容。

协议与预览实现参考：[MCP 工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[MDN srcdoc 隔离说明](https://developer.mozilla.org/en-US/docs/Web/API/HTMLIFrameElement/srcdoc)。

## 后续扩展成 App

2.4.0 起，工作台可以安装成应用（PWA），见 [APP.md](APP.md)。这套 HTML、模块化 JS、HTTP API 与 MCP 可以继续复用；需要商店上架、系统通知或本地文件时，再加原生外壳。

本地启动器已经承担模型连接、收件箱处理以及成果发布。经由模型 API 创建的成员处理文本和上述四类共享交付。需要终端、文件或外部业务系统时，应连接具备相应工具与权限的运行端。
